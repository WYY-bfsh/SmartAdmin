# SmartAdmin 部署文档

适用：新装 Ubuntu（账号 `ubuntu`）、腾讯云等云主机。  
技术：Java 17 + Spring Boot 3、Web 后台 JavaScript、商城 H5（uni-app）。  
方式：**Docker Compose 编排**，Java 只用仓库里那一份 Dockerfile。宿主机不装 JDK。

**现在只做第 4 章（生产套 8080 部署测试）。** 测试套、GitHub、Jenkins、第二个项目见第 6～8 章，第一套通过前不要做。

## 2. 架构与端口

```
浏览器 / 手机
   │
   ├── :8080  生产 Nginx（本期只开这一套）
   │         ├── /         Web 后台
   │         ├── /app/     商城 H5
   │         ├── /upload/  本地上传（卷 upload-data）
   │         └── /api/     反代 Java（去掉 /api 前缀）
   │                       ├── MySQL 8（库 smart_admin_v3）
   │                       └── Redis 7
   │
   └── :8082  测试套（第一套通过后再做，独立 Compose + 独立库）
```

Web 与 H5 共用同一套后端和 `/api`。打到 Nginx 后面时前端使用 `VITE_APP_API_URL='/api'`。


| 环境  | 在哪跑                     | 对外端口     | 目录                      | Compose 项目名       | 现在做不做      |
| --- | ----------------------- | -------- | ----------------------- | ----------------- | ---------- |
| 开发  | 程序员本机（Java 1024 + Vite） | 不占云主机    | 本地仓库                    | 不用                | 本机自己跑      |
| 测试  | 云主机                     | **8082** | `/data/smartadmin-test` | `smartadmin-test` | 第 4 章通过后再做 |
| 生产  | 云主机                     | **8080** | `/data/smartadmin`      | `smartadmin`      | **第 4 章**  |


第二个业务项目以后用 **8081 / 8083**。Jenkins 另开端口，不要抢 8080。

隔离靠「独立实例」，不是只改端口：每套自己的 Nginx、Java、MySQL、Redis、上传卷。禁止测试连生产库。

## 3. 上线前准备



### 3.1 机器

- 只测一套：建议 **2 核 4G**，磁盘 ≥ 40G  
- 同一台再起测试 + 生产：建议 **4 核 8G**  
- 2G 内存先加 swap（见 10.2）  
- 系统：Ubuntu 20.04 / 22.04 / 24.04  
- 本机 Windows：能双击 `deploy\打包.bat`；上传用 WinSCP（不必装 Git Bash）



### 3.2 安全组


| 端口                 | 是否开放  | 说明            |
| ------------------ | ----- | ------------- |
| 22                 | 是     | SSH，建议限制来源 IP |
| 8080               | 是     | 本期生产套         |
| 8082               | 测试套再开 |               |
| 80 / 443           | 有域名再开 |               |
| 3306 / 6379 / 1024 | **否** | 仅容器内网         |




### 3.3 安装 Docker

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker ubuntu
newgrp docker
docker --version
docker compose version
```

`permission denied` 时重新 SSH 登录再试。



### 3.4 配镜像加速（必做，否则 compose 必卡）

国内直连 `docker.io` 拉 `maven` / `eclipse-temurin` / `redis` / `nginx` 会超时（本项目已实测踩过 node:20-alpine 和 redis 两次）。先配好再往下走：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'JSON'
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://docker.m.daocloud.io"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "20m", "max-file": "3" }
}
JSON
sudo systemctl restart docker
docker info | grep -A 3 "Registry Mirrors"
```

> `mirror.ccs.tencentyun.com` 只在腾讯云内网可用（本项目服务器正是）。非腾讯云机器删掉这一条，或用 `docker.m.daocloud.io`。
>
> `log-opts` 是防止容器日志把磁盘写满 —— 不配的话 `smartadmin-api` 跑几个月就能吃掉几十 G。

预拉基础镜像（避免首次 `up --build` 时才发现拉不动）：

```bash
for i in mysql:8.0 redis:7-alpine nginx:alpine maven:3.9-eclipse-temurin-17 eclipse-temurin:17-jre-alpine; do
  echo "--- $i ---"; docker pull "$i" || echo "FAIL $i"
done
```

配好镜像源后，构建前端就不必再写 `docker.m.daocloud.io/library/node:20-alpine` 这种前缀，直接 `node:20-alpine` 即可。

## 4. 第一个项目部署测试（只起 8080）

目标（全打勾才算过）：

- [ ] 四个容器 `Up`：MySQL、Redis、Java、Nginx  
- [ ] 服务器 `curl` 验证码接口返回 JSON  
- [ ] 浏览器能打开 Web 并登录  
- [ ] 浏览器能打开 H5  
- [ ] 改过 `url-prefix` 后，后台上传图片能访问  

库密已改掉默认值，收在 `deploy/.env`（本机和服务器各一份，均已 gitignore）。账号仍是 `admin` / `123456`，正式对外必须改（第 5 章）。  
本阶段 **不关联 GitHub**，本机点一下打包，再用 WinSCP 拖到服务器即可。

### 4.1 本机打包上传

不用 Git Bash，也不用敲 `tar` / `scp`。

**打包**

1. 用资源管理器打开 `d:\Personal\project\smartadmin\deploy`
2. 双击 **`打包.bat`**，等窗口出现「打包完成」
3. 到上一级目录 `d:\Personal\project\smartadmin` 找到 **`smartadmin-src.zip`**

脚本会带上 `deploy`、Java、Web、H5、MySQL 脚本，并排除 `node_modules`、`.git`、`dist`。

双击后窗口一闪就关：在 `deploy` 文件夹空白处按住 Shift → 右键 →「在此处打开 PowerShell 窗口」，执行 `.\打包.ps1`。

**上传**

1. 安装并打开 [WinSCP](https://winscp.net/)
2. 协议 SFTP，主机填服务器公网 IP，用户名 `ubuntu`，密码是你的 SSH 密码
3. 左边选中 `smartadmin-src.zip`，拖到右边 **`/home/ubuntu/`**

不要传到 `/data/`（那是 root 目录，后面解压会没权限）。

### 4.2 服务器解压

```bash
sudo apt update
sudo apt install -y unzip
sudo mkdir -p /data/smartadmin
sudo unzip -o /home/ubuntu/smartadmin-src.zip -d /data/smartadmin
sudo mkdir -p /data/smartadmin/sql
sudo mv "/data/smartadmin/数据库SQL脚本/mysql/smart_admin_v3.sql" /data/smartadmin/sql/
sudo rm -rf "/data/smartadmin/数据库SQL脚本"
sudo chown -R ubuntu:ubuntu /data/smartadmin
ls /data/smartadmin
ls /data/smartadmin/sql/smart_admin_v3.sql
```

应有：`deploy`、`smart-admin-api-java17-springboot3`、`smart-admin-web-javascript`、`smart-app`、`sql`。

```
/data/smartadmin/
├── deploy/
│   ├── docker-compose.yml
│   ├── nginx/conf.d/smartadmin.conf
│   ├── 打包.bat / 打包.ps1
│   └── 部署文档.md
├── smart-admin-api-java17-springboot3/
├── smart-admin-web-javascript/
├── smart-app/
└── sql/smart_admin_v3.sql
```

`sql/` **只放** `smart_admin_v3.sql`。不要把 `sql-update-log` 放进去。已有数据的库再次启动不会重新导入 SQL。

### 4.3 改上传地址（测图片必做）

编辑：

`/data/smartadmin/smart-admin-api-java17-springboot3/sa-base/src/main/resources/prod/sa-base.yaml`

```yaml
      url-prefix: http://YOUR_IP:8080/upload/
```

未改的后果：图片 URL 会退回成 `http://175.27.131.7/upload/`（没有 `:8080`），页面上的图全部 404。该项打进 jar，**改完必须重新构建后端**。

> **回归风险（本项目已踩过）**：这个值曾经只在服务器上被 sed 改对，仓库里没改。结果只要重新打包上传或从 Gitee 拉代码，就会把服务器上正确的文件覆盖回错的。**改代码前先搜一次 `175.27.131.7`，确认仓库里带的是 `:8080`。**

### 4.4 构建前端

```bash
cd /data/smartadmin

docker run --rm -v /data/smartadmin/smart-admin-web-javascript:/app -w /app \
  node:20-alpine sh -c \
  "npm config set registry https://registry.npmmirror.com && npm install && npm run build:prod"

test -f /data/smartadmin/smart-admin-web-javascript/dist/index.html && echo WEB_OK

docker run --rm -v /data/smartadmin/smart-app:/app -w /app \
  node:20-alpine sh -c \
  "npm config set registry https://registry.npmmirror.com && npm install && npm run build:h5"

test -f /data/smartadmin/smart-app/dist/build/h5/index.html && echo H5_OK
```

H5 在 alpine 失败则把镜像换成 `node:18`。  
`manifest.json` 里 `h5.router.base` 已是 `/app/`，不要改成 `/`，除非同时改 Nginx。

仓库里 `.env.test` / `.env.development` 仍是 `http://127.0.0.1:1024`，只给本机开发用。上服务器必须走 `/api`（生产 `.env.production` 已是这样）。

### 4.5 启动四件套

**先确认 `deploy/.env` 在。** compose 里 MySQL 密码和后端数据源密码都读它，文件不在会直接报错退出（这是故意的，避免两个密码悄悄分叉）：

```bash
cd /data/smartadmin/deploy
cat .env                      # 应有一行 MYSQL_ROOT_PASSWORD=xxx
docker compose config >/dev/null && echo COMPOSE_OK
```

`COMPOSE_OK` 出来了才继续：

```bash
docker compose -p smartadmin up -d --build
```

compose 里已有 `name: smartadmin`，`-p smartadmin` 可省，写上不冲突。

首次编 Java 依赖 Maven Central，服务器实测约 1.5MB/s，正常 5～15 分钟。`settings.xml`（阿里云镜像）由 Dockerfile 的 `COPY settings.xml /root/.m2/settings.xml` 带入 —— 少了这一行，`dependency:go-offline` 会偶发 EOF。

```bash
docker compose -p smartadmin ps
docker compose -p smartadmin logs -f sa-admin
```

`Ctrl+C` 只退日志。四个容器：`smartadmin-mysql`、`smartadmin-redis`、`smartadmin-api`、`smartadmin-nginx`，均为 `Up`（mysql 可先 `starting`，一两分钟内应变 healthy）。

改完后端记得同步重启 Nginx（原因见 4.6）：

```bash
docker restart smartadmin-api && docker restart smartadmin-nginx
```

### 4.5.1 导入项目扩展表（首次部署必做，最容易漏）

`sql/smart_admin_v3.sql` 只有**官方的 44 张系统表**。秒杀商城 / 媒体中心 / 客服 / 微信支付这四块业务，表在 `restore-project-modules.sql` 里（21 张表 + 40 个菜单 + 超管授权），**首次部署必须手工导一次**。

**漏了会怎样**：库能起、登录也正常、页面能打开 —— 只是左侧菜单少四组，点什么都空。最容易被当成「部署成功」交出去。

```bash
cd /data/smartadmin/deploy
set -a; . ./.env; set +a          # 读出 MYSQL_ROOT_PASSWORD

docker exec -i smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" smart_admin_v3 \
  < /data/smartadmin/restore-project-modules.sql

docker exec smartadmin-redis redis-cli -n 1 FLUSHDB   # 清掉缓存的权限/菜单
docker restart smartadmin-api
docker restart smartadmin-nginx
```

脚本是幂等的（`INSERT ... SELECT ... WHERE NOT EXISTS`），重复执行不会重复插入，可以放心重跑。也可以直接跑封装好的：

```bash
bash /data/smartadmin/deploy/恢复数据库.sh     # 会连官方库一起重建，慎用
```

核对（**基准值：表 65 = 官方 44 + 本项目 21；t_menu 179 = 官方 139 + 本项目 40**）：

```bash
docker exec smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -e "
SELECT COUNT(*) AS 表数 FROM information_schema.tables WHERE table_schema='smart_admin_v3';
SELECT COUNT(*) AS 菜单数 FROM smart_admin_v3.t_menu;"
```

低于基准就是没导进去。

### 4.9 数据库被清空后怎么恢复

官方系统表在 `smart_admin_v3.sql`。Web/H5 后来加的模块**不是一面一表**：

| 端 | 模块 | 实际用到的表 |
|---|---|---|
| Web+H5 | 秒杀商城 | `t_mall_member` `t_mall_address` `t_seckill_activity` `t_mall_order` `t_mall_express_trace` `t_mall_commission` `t_mall_setting` |
| Web | 媒体中心（AI/音乐/影月几十个页） | `t_media_ai_*` `t_media_music_*` `t_media_video*` `t_media_catalog` `t_media_user_action` |
| Web | 客服 | `t_cs_ticket` `t_cs_ticket_message` `t_cs_knowledge` `t_cs_qa` |
| Web | 微信支付 | `t_pay_order` |
| Web+H5 | 员工/公告/商品/企业等 | 已在官方 `smart_admin_v3.sql` |

以上自建表 + 菜单 + 超管权限打在 **`restore-project-modules.sql`**。Java `@TableName` 已全部覆盖，没有更多业务表。

**服务器（推荐用脚本，它会自动找路径、自动读 `deploy/.env` 的密码）：**

```bash
cd /data/smartadmin
sudo chmod +x deploy/恢复数据库.sh
bash deploy/恢复数据库.sh
```

脚本会依次找 `sql/smart_admin_v3.sql`（也认 `sql-src/`、`数据库SQL脚本/mysql/`）和 `restore-project-modules.sql`（也认项目根目录），找不到会**明确报错退出**，不会静默跳过。密码来源：环境变量 `MYSQL_ROOT_PASSWORD` > `deploy/.env`。

> 旧版脚本有个坑已修：它去导 `media-center.sql` / `customer-service.sql` / `wechat-pay.sql`，这三个文件项目里并不存在，会被静默跳过 —— 结果是库起来了、能登录，但业务菜单和表全丢，很难发现。现在脚本结束会直接打印表数和菜单数供核对。

手工导入（效果相同）：

```bash
cd /data/smartadmin/deploy
set -a; . ./.env; set +a

# 会删掉当前 smart_admin_v3 再重建，业务数据不可恢复
docker exec -i smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" \
  < /data/smartadmin/sql/smart_admin_v3.sql

docker exec -i smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" smart_admin_v3 \
  < /data/smartadmin/restore-project-modules.sql

docker exec smartadmin-redis redis-cli -n 1 FLUSHDB
docker restart smartadmin-api
docker restart smartadmin-nginx
```

核对（基准：**表 65，菜单 179**）：

```bash
docker exec smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -e "
SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='smart_admin_v3';
SELECT COUNT(*) FROM smart_admin_v3.t_menu;"
```

应能看到官方的 `t_employee`、`t_menu` 等，以及 `t_mall_*`、`t_media_*`、`t_cs_*`、`t_pay_order`。  
登录仍是 `admin` / `123456`。以前业务数据（订单、会员）无法从脚本找回，脚本只有结构和官方初始数据。

不要再执行 `sql-update-log/v3.15.0.sql` 等带版本号的文件，它们已经打进 `smart_admin_v3.sql`。

## 5. 正式对外

### 5.1 必改

- [ ] `deploy/.env` 里设强密码（`MYSQL_ROOT_PASSWORD=...`），**compose 不再写死密码**，MySQL 和后端都读这一个变量，从根上避免两处分叉

### 5.2 备份

```bash
sudo mkdir -p /data/backup
docker exec smartadmin-mysql \
  sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" smart_admin_v3' \
  | gzip > /data/backup/smart_admin_v3-$(date +%Y%m%d).sql.gz
```

建议 crontab 每天执行，保留 7～14 天。  
回滚：前端覆盖上一份 `dist`；后端用上一版源码重新 `--build sa-admin`；库导入最近一份 `sql.gz`。

### 5.3 增量 SQL

按 `数据库SQL脚本/mysql/sql-update-log/` 版本从小到大：

```bash
docker exec -i smartadmin-mysql \
  mysql -uroot -p你的密码 smart_admin_v3 < /path/to/xxx.sql
```



### 5.4 域名与 HTTPS

1. 域名 A 记录指向公网 IP，安全组开放 80、443。
2. `url-prefix` 改为 `https://你的域名/upload/`，重建后端。
3. 接口仍走同域 `/api`。
4. 可用宿主机 Nginx 终结 TLS 再反代 `127.0.0.1:8080`，或把证书挂进现有 Nginx 容器。

无域名时继续 `http://公网IP:8080`。

生产环境禁止 `docker compose down -v`（会删卷）。

并先把 `.env.test` 的 `VITE_APP_API_URL` 改成 `'/api'`。H5 同样用 `/api`，路由仍为 `/app/`。

若开发也要塞进服务器：目录 `/data/smartadmin-dev`，端口 **8088**，库可随时清空，**禁止连生产库**。一般不推荐，内存会很紧。

## 7. 和 GitHub 关联（不是必须）

Compose 上线 **不依赖** GitHub。关联的意思是：代码以仓库为准，pull 或推送后发布。


| 阶段  | 做法                                     | 何时       |
| --- | -------------------------------------- | -------- |
| 0   | 双击打包.bat + WinSCP 上传 zip（第 4 章） | **现在**   |
| 1   | 服务器 `git clone` / `git pull` 再 compose | 测试套要天天更新 |
| 2   | GitHub Actions 或 Jenkins Webhook       | 要自动、可审计  |


顺序：阶段 0 测通 → 测试环境阶段 1 → 稳定后再阶段 2。Jenkins 和 Actions 二选一即可。

**阶段 1：** GitHub 私有库 + 服务器 Deploy Key（只读）→

```bash
sudo mkdir -p /data/repos
cd /data/repos
git clone git@github.com:你的账号/smartadmin.git smartadmin
```

测试更新：`git checkout develop && git pull`，构建前端后 `docker compose -p smartadmin-test up -d --build`。  
生产只拉 tag，例如 `git checkout v1.0.0`，不要跟踪 `develop`。

**阶段 2：**

- Actions：`develop` → 测 8082；`main` / tag → 生产 8080（建议手动确认）。Secrets 放 IP、SSH 钥、路径，密码不要进仓库。  
- Jenkins：GitHub Webhook → Job 里 `docker build` / `compose`，JDK 用镜像。


| 分支                      | 环境           |
| ----------------------- | ------------ |
| `develop`               | 本机开发 / 可选开发机 |
| `develop` 或 `test` 自动发布 | 测试 8082      |
| `main` + tag            | 生产 8080      |

## 8. 第二个项目与 Jenkins

多个项目、Java 版本不同时：**每个项目一份 Dockerfile（锁死该项目 JDK）+ 一份 Compose**。Ubuntu 上不要装 JDK 8 + 17。

```
/data/
├── smartadmin/           8080
├── smartadmin-test/      8082
├── 另一个项目/            8081
└── jenkins/              8090（或 8088）
```

Jenkins 也用容器。流水线用指定版本的 Maven/Java 镜像构建，不要在 Agent 上装一套全局 JDK。  
Docker 套接字可挂给 Jenkins 以便本机 `compose up`，等于给了 Docker 权限，账号和插件要管严。

## 9. 日常发布（生产套）

```bash
cd /data/smartadmin/deploy
```

## 10. 排错与附录


| 现象              | 处理                                      |
| --------------- | --------------------------------------- |
| 本机 curl 通，外网打不开 | 安全组未放行 8080                             |
| 容器 Exited       | `docker compose -p smartadmin logs 服务名` |
| 后端反复重启          | 连不上库/Redis，或 `deploy/.env` 密码和库里的不一致   |
| `/api/` 全 502    | 后端刚重启完还没起来（Spring 启动约 1 分钟），或 nginx 缓存了旧 IP → `docker restart smartadmin-nginx` |
| 页面出了登录失败        | 未用 production 构建，或 `/api` 反代失败          |
| H5 刷新 404       | Nginx `/app/` 的 `try_files` 被改坏         |
| 图片 404          | `url-prefix` 仍是旧 IP，或未重建后端              |
| 构建被杀            | 内存不足，加 swap 或升配                         |
| **nginx 起不来**，报 `create mountpoint ...: read-only file system` | 有挂载点嵌在另一个**只读**挂载里。当前 compose 的 `/usr/share/nginx/html(app)` 必须让父目录可写；或把 Web / H5 / upload 挂成三个**平级**目录（推荐，可全 `:ro`） |
| **`恢复数据库.sh` 报 `set: pipefail: invalid option name`** | 文件是 CRLF。`sed -i 's/\r$//' 文件`，并确认仓库里有 `.gitattributes`。`.env` 同样会因 CRLF 让密码多带 `\r` |
| **nginx 报 `unknown directive ""`** | 配置文件开头有 UTF-8 BOM（Windows 工具写入所致）。用 `head -c 3 文件 \| od -An -tx1` 应不是 `ef bb bf` |
| **菜单少四组，但登录正常** | 漏了 4.5.1 导入 `restore-project-modules.sql`。核对表 65 / 菜单 179 |
| `docker compose` 拉镜像超时 | 没配 3.4 的镜像加速，或配完没 `sudo systemctl restart docker` |
| 日志把磁盘写满 | `daemon.json` 里的 `log-opts` 没配（见 3.4） |




### 10.1 为什么用 Compose 而不是只写 Dockerfile

Dockerfile 只做**一个**镜像。本项目要同时跑 MySQL、Redis、Java、Nginx。Compose 是清单；Java 的 Dockerfile 给 Compose 的 `build:` 用。

### 10.2 2G 内存加 swap

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```



### 10.3 责任边界

- 对外只暴露 Nginx。  
- 默认账号、默认库密不得带入正式环境。  
- 测试套禁止连生产库。  
- 宿主机保持干净，只跑 Docker。
