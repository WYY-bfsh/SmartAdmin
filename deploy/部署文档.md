# SmartAdmin 部署文档

适用：新装 Ubuntu（账号 `ubuntu`）、腾讯云等云主机。
技术：Java 17 + Spring Boot 3、Web 后台 JavaScript、商城 H5（uni-app）。
方式：**Docker Compose 编排**，Java 只用仓库里那一份 Dockerfile，宿主机不装 JDK。

**当前生产状态：已上线。** `http://175.27.131.7:8080` 与 `/app/` 均可用，验收结果见 1.2。

## 3. 上线前准备

### 3.1 机器

- 只测一套：建议 **2 核 4G**，磁盘 ≥ 40G
- 同一台再起测试 + 生产：建议 **4 核 8G**
- 2G 内存先加 swap（见 10.3）
- 系统：Ubuntu 20.04 / 22.04 / 24.04
- 本机 Windows：能双击 `deploy\打包.bat`；上传用 WinSCP

### 3.2 安全组

| 端口 | 是否开放 | 说明 |
| --- | --- | --- |
| 22 | 是 | SSH，建议限制来源 IP |
| 8080 | 是 | 生产套 |
| 8082 | 测试套再开 | |
| 80 / 443 | 有域名再开 | |
| 3306 / 6379 / 1024 | **否** | 仅容器内网 |

### 3.3 安装 Docker

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker ubuntu
newgrp docker
docker --version
docker compose version
```

`permission denied` 时重新 SSH 登录再试。

### 3.4 配镜像加速（**必做**，否则 compose 必卡）

国内直连 `docker.io` 拉 `maven` / `eclipse-temurin` / `redis` / `nginx` 会超时（本项目已实测踩过 `node:20-alpine` 和 `redis` 两次）。先配好再往下：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'JSON'
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://docker.m.daocloud.io"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "20m", "max-file": "3" }
}
JSON
sudo systemctl restart docker
docker info | grep -A 3 "Registry Mirrors"
```

> `mirror.ccs.tencentyun.com` 只在腾讯云内网可用（本项目服务器正是）。非腾讯云机器删掉这条，只用 `docker.m.daocloud.io`。
> `log-opts` 防止容器日志把磁盘写满 —— 不配的话 `smartadmin-api` 跑几个月能吃几十 G。

预拉基础镜像（避免首次 `up --build` 才发现拉不动）：

```bash
for i in mysql:8.0 redis:7-alpine nginx:alpine maven:3.9-eclipse-temurin-17 eclipse-temurin:17-jre-alpine; do
  echo "--- $i ---"; docker pull "$i" || echo "FAIL $i"
done
```

配好之后，构建前端直接用 `node:20-alpine` 即可，不必再写 `docker.m.daocloud.io/library/` 前缀。

### 3.5 关键文件与密码机制

密码**只有一处来源**：`deploy/.env`

```
# deploy/.env（本机与服务器各一份，均已 gitignore，不进 Gitee）
MYSQL_ROOT_PASSWORD=<库密码>
```

compose 里 MySQL 和后端数据源都读这一个变量：

```yaml
MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?set MYSQL_ROOT_PASSWORD in deploy/.env}
SPRING_DATASOURCE_PASSWORD: ${MYSQL_ROOT_PASSWORD:?set MYSQL_ROOT_PASSWORD in deploy/.env}
```

**故意写成写死值会出的事**：本机与服务器两份 compose 必然分叉（历史上就是这样），一旦用 zip/git 覆盖服务器，密码退回默认值 → 后端连不上库。

**`COMPOSE_OK` 是硬门槛**：

```bash
cd /data/smartadmin/deploy
docker compose config >/dev/null && echo COMPOSE_OK
```

报 `set MYSQL_ROOT_PASSWORD in deploy/.env` 就是 `.env` 没上传或写错，先修再往下走。

#### 轮换库密码必须两步走（很容易只做一步）

MySQL 只在**首次初始化空数据卷**时读 `MYSQL_ROOT_PASSWORD`。之后改 `.env` 再重启，**库里的密码不会变** —— 结果是 `.env` 和库里对不上，后端直接连不上库。

正确做法（`ALTER USER` + 改 `.env`，两步都做）：

```bash
cd /data/smartadmin/deploy
set -a; . ./.env; set +a
OLD="$MYSQL_ROOT_PASSWORD"
NEW='你的新密码'

docker exec -i smartadmin-mysql mysql -uroot -p"$OLD" <<SQL
ALTER USER 'root'@'%' IDENTIFIED BY '${NEW}';
ALTER USER 'root'@'localhost' IDENTIFIED BY '${NEW}';
FLUSH PRIVILEGES;
SQL

printf 'MYSQL_ROOT_PASSWORD=%s\n' "$NEW" > /data/smartadmin/deploy/.env
docker compose -p smartadmin up -d sa-admin mysql
docker restart smartadmin-nginx
```

本机 `deploy/.env` 也要同步改成同一个值，否则两边不一致。

> 2026-09-13 09:01 库密码轮换过一次，`.env` 两侧已同步。
> 顺手提醒：`root` 密码同时也是**唯一**的库账号密码（后端就用 root 连），所以它必须足够强。
> 另外 `SPRING_DATASOURCE_URL` 里带了 `allowPublicKeyRetrieval=true`（MySQL 8 用 caching_sha2_password 且连接不走 TLS 时必需），别删。

### 4.1 本机打包上传

不用 Git Bash，也不用敲 `tar` / `scp`。

**打包**

1. 用资源管理器打开 `D:\Personal\project\smartadmin\deploy`
2. 双击 **`打包.bat`**，等窗口出现「打包完成」
3. 到上一级目录找到 **`smartadmin-src.zip`**（约 25MB）

脚本会带上 `deploy`、Java、Web、H5、MySQL 脚本，并排除 `node_modules`、`.git`、`dist`、`target`。
双击后窗口一闪就关：在 `deploy` 文件夹空白处按住 Shift → 右键 →「在此处打开 PowerShell 窗口」，执行 `.\打包.ps1`。

**上传**

1. 安装并打开 [WinSCP](https://winscp.net/)
2. 协议 SFTP，主机填公网 IP，用户名 `ubuntu`，密钥/密码用你的 SSH 凭据
3. 左边选中 `smartadmin-src.zip`，拖到右边 **`/home/ubuntu/`**

不要传到 `/data/`（那是 root 目录，后面解压会没权限）。

```bash
sudo rm -rf "/data/smartadmin/数据库SQL脚本"
sudo chown -R ubuntu:ubuntu /data/smartadmin
ls /data/smartadmin
ls /data/smartadmin/sql/smart_admin_v3.sql
```

```

│   ├── .env                     ← 库密码（gitignore，别被 zip 覆盖）
│   ├── docker-compose.yml
│   ├── nginx/conf.d/smartadmin.conf
│   ├── 恢复数据库.sh
│   ├── 打包.bat / 打包.ps1
```

### 4.3 确认上传地址（测图片必做）

编辑 `smart-admin-api-java17-springboot3/sa-base/src/main/resources/prod/sa-base.yaml`：

```yaml
      url-prefix: http://175.27.131.7:8080/upload/
```

未改 / 写错的后果：图片 URL 会变成没有 `:8080` 的地址，页面上图全部 404。该项打进 jar，**改完必须重新构建后端**。

仓库里 `.env.test` / `.env.development` 仍是 `http://127.0.0.1:1024`，只给本机开发用。上服务器必须走 `/api`（`.env.production` 已是）。

### 4.5 启动四件套

```bash
cd /data/smartadmin/deploy
docker compose config >/dev/null && echo COMPOSE_OK     # 先过硬门槛
nohup docker compose -p smartadmin up -d --build > /tmp/sa_up.log 2>&1 < /dev/null &
tail -f /tmp/sa_up.log
```

**为什么用 nohup**：构建开始后 SSH 断了 dockerd 也会继续编，但 compose 客户端断了就不会走到 `up` 那一步。

compose 里已有 `name: smartadmin`，`-p smartadmin` 可省，写上不冲突。

首次编 Java 依赖 Maven Central，服务器实测约 **1.5MB/s**，约 3 分钟进到 `up`。`dependency:go-offline` 会静默好几分钟（`-q` 不打印进度），**不是卡死**，看 `free -m` 有没有变化即可。
`settings.xml`（阿里云镜像）由 Dockerfile 的 `COPY settings.xml /root/.m2/settings.xml` 带入 —— 少了这一行会偶发 EOF。

```bash
docker compose -p smartadmin ps
docker compose -p smartadmin logs -f sa-admin            # Ctrl+C 只退日志
```

四个容器：`smartadmin-mysql`（可先 `starting`，1～2 分钟变 healthy）、`smartadmin-redis`、`smartadmin-api`、`smartadmin-nginx`。
首次 MySQL init 会自动执行 `sql/smart_admin_v3.sql`（180KB），healthcheck 给了 300 秒，不必慌。

### 4.6 导入项目扩展表（**最容易漏的一步**）

`sql/smart_admin_v3.sql` 只有**官方的 44 张系统表**。秒杀商城 / 媒体中心 / 客服 / 微信支付这四块业务，表在 `restore-project-modules.sql` 里（21 张表 + 40 个菜单 + 超管授权），**首次部署必须手工导一次**。

**漏了会怎样**：库能起、登录也正常、页面能打开 —— 只是左侧菜单少四组，点什么都空。**最容易被当成「部署成功」交出去。**

```bash
cd /data/smartadmin/deploy
set -a; . ./.env; set +a          # 读出 MYSQL_ROOT_PASSWORD

docker exec -i smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" smart_admin_v3 \
  < /data/smartadmin/restore-project-modules.sql

docker exec smartadmin-redis redis-cli -n 1 FLUSHDB   # 清掉缓存的权限/菜单
docker restart smartadmin-api
docker restart smartadmin-nginx
```

或者直接跑封装好的脚本（它会自动找路径、读 `.env`、结束打印表数/菜单数）：

```bash
cd /data/smartadmin && bash deploy/恢复数据库.sh
```

> 该脚本同时会 **DROP 并重建官方库**，已有业务数据时慎用；首次部署或库被清空后重建时用。

核对（**基准：表 65，菜单 179**）：

```bash
docker exec smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -e "
SELECT COUNT(*) AS 表数 FROM information_schema.tables WHERE table_schema='smart_admin_v3';
SELECT COUNT(*) AS 菜单数 FROM smart_admin_v3.t_menu;"
```

低于基准就是没导进去（脚本幂等，可放心重跑）。

**表数对了不等于字段对。** 表数/菜单数只是最低门槛，字段级差异照样能让页面报错。
本项目 2026-09-13 就发现 `restore-project-modules.sql` 漏了 Java 在用的 2 个列：

| 表 | 列 | 说明 |
| --- | --- | --- |
| `t_mall_member` | `commission_level` | 二级分销等级 |
| `t_seckill_activity` | `commission_rate_l2` | 二级佣金比例 |

（线上库是后补的，**SQL 文件已同步补上**，新库直接导入不会再缺。）已有的库对不上时手工补：

```bash
docker exec -i smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" smart_admin_v3 -e "
ALTER TABLE t_mall_member       ADD COLUMN commission_level   int            DEFAULT NULL COMMENT '二级分销等级';
ALTER TABLE t_seckill_activity  ADD COLUMN commission_rate_l2 decimal(6,4)   DEFAULT NULL COMMENT '二级佣金比例';"
```

**重建库后建议全量对一次字段**，把线上字段和 SQL 文件比一遍（比数表数量靠谱得多）：

```bash
# 1) 导出线上字段
docker exec smartadmin-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -e "
SELECT CONCAT(table_name,'.',column_name) FROM information_schema.columns
WHERE table_schema='smart_admin_v3' AND table_name LIKE 't_mall%'
```

## 6. 本轮踩到的 5 个坑（重要）

都是「跑一次成功、下一次部署翻车」的类型：

### 坑 1（最危险）：`url-prefix` 只在服务器上被改对，仓库里是错的

服务器是 `http://175.27.131.7:8080/upload/`，**本机仓库少了 `:8080`**（当初用 sed 只改了服务器）。重新打包或 Gitee 拉码就会用错值覆盖对的 → 上传图片全 404。
→ 已修本机。改后端前先搜一次 `175.27.131.7`。

### 坑 2：`恢复数据库.sh` 旧版会「静默半成品」

旧版依次导 `media-center.sql` / `customer-service.sql` / `wechat-pay.sql`，**这三个文件项目里根本不存在**，被无声跳过；只导到 `restore-mall.sql` 的 7 张商城表。
→ **库能起、能登录、页面能开，但业务菜单和 21 张表全丢**。已重写：多路径探测、找不到明确报错、结束打印表数/菜单数。

### 坑 3：Nginx 只读挂载嵌套导致容器起不来（本次实际卡住的唯一一个）

原 compose 把 Web 挂到 `/usr/share/nginx/html:ro`，再把 H5 挂到 `/usr/share/nginx/html/app:ro`。Docker 要为第二个挂载创建挂载点，而此时父目录已是**只读**挂载 → 直接失败：

```
error mounting ".../smart-app/dist/build/h5" to rootfs at "/usr/share/nginx/html/app":
create mountpoint ...: read-only file system
```

**这是确定性的，每次都会失败**，不是偶发。当前解法是让父目录可写：

```yaml
volumes:
  - ./nginx/conf.d:/etc/nginx/conf.d:ro
  - ../smart-admin-web-javascript/dist:/usr/share/nginx/html        # 去掉 :ro，Docker 才能建出 app 挂载点
  - ../smart-app/dist/build/h5:/usr/share/nginx/html/app:ro
  - upload-data:/upload:ro
```

代价：宿主 `dist/` 里会多一个被盖住的空 `app/` 目录（无害）。
**更干净的写法**是把三者挂成**平级**（如 `/srv/web`、`/srv/app`、`/srv/upload`），这样全部可以 `:ro`，也不用往 dist 里写东西。本期没动线上，避免改一个已跑通的配置。

### 坑 4：CRLF 换行符

Linux 上跑 Windows 写出的文件：

- `恢复数据库.sh` 的 `set -euo pipefail` 变成 `...pipefail\r` → 报 **`set: pipefail: invalid option name`**，脚本第一句就死
- `deploy/.env` 密码值结尾多一个 `\r` → 连库认证失败

→ 已把 8 个部署文件全转 LF，并加 **`.gitattributes`**（`*.sh`/`Dockerfile`/`docker-compose*.yml`/`*.conf` 强制 `eol=lf`，`*.bat`/`*.ps1` 保持 crlf）防复发。上传前自检：`tr -dc '\r' < 文件 | wc -c` 应为 0。

### 坑 5：4 个基础镜像缺失 + docker.io 直连超时

`maven:3.9-eclipse-temurin-17`、`eclipse-temurin:17-jre-alpine`、`redis:7-alpine`、`nginx:alpine` 从没拉过，而 docker.io 直连会超时。
→ 见 3.4 的镜像加速。

### 附带修的

- `settings.xml`（阿里云 Maven 镜像）建好了但 Dockerfile **没 COPY 进去**，等于不存在 → 补上 `COPY settings.xml /root/.m2/settings.xml`。
- 本机 `docker-compose.yml` / `nginx.conf` 带 **UTF-8 BOM**（服务器没有）→ 已去 BOM。按文档用 zip 覆盖上传会让 nginx 报 `unknown directive`。
- 新增 `.dockerignore`（排除 `target/`、`.idea`），构建上下文从几十 MB 降到 120KB。
- `.gitignore` 补 `deploy/.env`、`deploy/生产密码.txt`、`*.zip`（`smartadmin-src.zip` 有 25MB，别进 Gitee）。
- compose 加 `name: smartadmin`，忘了 `-p` 也不会另起一套项目 + 一套空卷。

## 10. 排错与附录

### 10.1 排错表

| 现象 | 处理 |
| --- | --- |
| 本机 curl 通，外网打不开 | 安全组未放行 8080 |
| 容器 Exited | `docker compose -p smartadmin logs 服务名` |
| 后端反复重启 | 连不上库/Redis，或 `deploy/.env` 密码与库里的不一致 |
| `/api/` 全 502 | 后端刚重启还没起来（约 1 分钟），或 nginx 缓存旧 IP → `docker restart smartadmin-nginx` |
| 页面登录失败 | 未用 production 构建，或 `/api` 反代失败 |
| H5 刷新 404 | Nginx `/app/` 的 `try_files` 被改坏 |
| 图片 404 | `url-prefix` 没带 `:8080`，或没重建后端 |
| 构建被杀 | 内存不足，加 swap 或升配 |
| **nginx 起不来**，报 `create mountpoint ...: read-only file system` | 挂载点嵌在另一个**只读**挂载里。当前 compose 必须让 `/usr/share/nginx/html` 可写；或把 Web/H5/upload 挂成三个**平级**目录（可全 `:ro`） |
| **`恢复数据库.sh` 报 `set: pipefail: invalid option name`** | 文件是 CRLF。`sed -i 's/\r$//' 文件`；`.env` 同样会因 CRLF 让密码多带 `\r` |
| **nginx 报 `unknown directive ""`** | 配置文件开头有 UTF-8 BOM。`head -c 3 文件 \| od -An -tx1` 不应是 `ef bb bf` |
| **菜单少四组，但登录正常** | 漏了 4.6 导入 `restore-project-modules.sql`。核对表 65 / 菜单 179 |
| 页面报 `Unknown column 'xxx'` | 表数对也可能缺字段（本项目踩过 2 个）。见 4.6 的字段比对与补齐 |
| 改了 `.env` 密码后后端连不上库 | 只改了 `.env` 没改库。必须 `ALTER USER` + 改 `.env` 两步，见 3.5 |
| `docker compose` 拉镜像超时 | 没配 3.4 的镜像加速，或配完没 `sudo systemctl restart docker` |
| 日志把磁盘写满 | `daemon.json` 里的 `log-opts` 没配（见 3.4） |

### 10.2 为什么用 Compose 而不是只写 Dockerfile

Dockerfile 只做**一个**镜像。本项目要同时跑 MySQL、Redis、Java、Nginx。Compose 是编排清单；Java 的 Dockerfile 给 Compose 的 `build:` 用。

### 10.3 2G 内存加 swap

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```
